## Berichten en events

**Twee soorten queues.** Eén consoleapp zet een queue van Service Bus naast een queue in Azure Storage. Bij Service Bus gaan de berichten als batch de queue in. Een `ServiceBusProcessor` haalt ze op, met een handler die elk bericht afrondt met `CompleteMessageAsync`. Bij de Storage-queue is alles een losse stap: kijken met `PeekMessagesAsync`, het aantal opvragen, een bericht ophalen en het daarna zelf verwijderen met de pop receipt. Dat aantal is een schatting: `ApproximateMessagesCount` kan hoger zijn dan wat er echt in de queue staat.

**Event Hubs op drie manieren lezen.** De module over Event Hubs leest dezelfde events op drie manieren:

- met `EventHubConsumerClient`, uit alle partities;
- met dezelfde client, uit één partitie vanaf het eerste event (`EventPosition.Earliest`);
- met een `EventProcessorClient`, de aanbevolen route.

De processor heeft een container in Blob Storage nodig. Daarin houdt hij bij welke lezer welke partitie heeft, en tot waar er gelezen is:

```csharp
var processorClient = new EventProcessorClient(
    new BlobContainerClient(StorageConnectionString, BlobContainerName),
    EventHubConsumerClient.DefaultConsumerGroupName,
    EventHubConnectionString,
    EventHubName);
```

Hoofdstuk 12 doet hetzelfde met een producer en een consumer in twee klassen. Tien events gaan erin, en een processor leest ze dertig seconden lang.

## Data

**Cosmos DB met een pre-trigger.** Orders gaan in een container met `/OrderAddress/City` als partition key. Elke query schrijft de kosten in request units naar de console. Een pre-trigger in JavaScript weigert een order zonder klant. Zo'n trigger draait niet vanzelf: de aanroep moet hem bij naam noemen.

```csharp
var createResponse = await Container!.CreateItemAsync(
    order, new PartitionKey(order.OrderAddress!.City),
    new ItemRequestOptions() { PreTriggers = [ "validateOrder" ] }
);
```

**Table Storage.** Klanten zijn entiteiten met het type klant als PartitionKey en de naam als RowKey. De app voegt ze toe of werkt ze bij met een upsert, en zoekt met OData-filters als `PartitionKey eq 'ReSellers'`.

**Blob Storage met metadata en index tags.** Een order gaat als JSON-blob in de Cool-tier, met metadata en een index tag voor de naam van de klant. Metadata lees je per blob. Op index tags kun je zoeken, over alle containers heen:

```csharp
var taggedBlobs = blobServiceClient.FindBlobsByTagsAsync(
    @$"@container = '{ContainerName}' AND ""CustomerName"" = '{customerName}'"
);
```

## Identiteit en geheimen

**MSAL met een tokencache.** Een consoleapp vraagt als public client een token aan voor `User.Read` en `Calendars.Read`. Eerst stil uit de cache, en pas bij een `MsalUiRequiredException` via de browser. De cache staat met `MsalCacheHelper` op schijf, dus na de eerste keer is inloggen niet meer nodig. Een tweede app haalt met zo'n token de naam van de gebruiker op uit Microsoft Graph.

**Managed identities.** Een oefening zet drie manieren naast elkaar om een token te krijgen:

- `DefaultAzureCredential` zonder opties;
- dezelfde, met de client-ID van een user-assigned identity;
- een `ChainedTokenCredential` die eerst de managed identity probeert en anders de Azure CLI.

Een function app met een user-assigned identity leest zo een geheim uit Key Vault, zonder sleutel in de configuratie.

**App Configuration.** Een Razor Pages-app haalt instellingen en een feature flag uit App Configuration. Het label is de naam van de omgeving, dus Development en Production lezen elk hun eigen waarden. Verandert `demofeature`, dan ververst de app zijn configuratie.

```csharp
options
    .Connect(connectionString)
    .UseFeatureFlags(option =>
        option.Select("demofeature", hostingContext.HostingEnvironment.EnvironmentName))
    .ConfigureRefresh(refreshOptions => refreshOptions.Register("demofeature"))
    .Select(KeyFilter.Any, hostingContext.HostingEnvironment.EnvironmentName);
```

## Infrastructuur, caching en CDN

- **ARM-templates.** Een linked template, dat een tweede template via een URL laadt, staat naast een nested template, dat het tweede template in hetzelfde bestand heeft. Twee parameterbestanden maken met één template een App Service plan voor Linux of voor Windows. Virtuele machines komen er met de Azure CLI en met PowerShell.
- **Containers.** Een image bouwen in de registry zelf met `az acr build`, en het draaien in Container Instances en in Container Apps.
- **Redis.** De datatypes van Redis één voor één: strings, een teller met een verlooptijd, lists, sets en hashes. Daarna cache-aside: eerst in de cache kijken, anders het object laden en het een minuut in de cache bewaren.
- **CDN.** Met de management-SDK een profiel en een endpoint maken, en de hele inhoud verversen met een purge op `/*`.
- **Functions.** De function apps gebruiken het isolated worker model, met `Microsoft.Azure.Functions.Worker`.
